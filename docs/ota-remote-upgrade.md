# 小安话机 · 远程升级（OTA）方案

> 目标：酒店里几十上百台话机，不拆机、不接线，从服务器下发新固件；升级失败自动回到旧版本。

---

## 1. 结论

| 问题 | 答案 |
|------|------|
| 能不能做 | **能**。ESP32-S3 原生支持 A/B 双槽 OTA，本工程所用 esp32 core 3.3.10 已自带 `Update` / `HTTPUpdate` 库，且 bootloader 编译时已开启 **自动回滚**（`CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y`）。 |
| 最大障碍 | 当前分区表**只有一个 app 槽**（app0，4 MB）。OTA 必须有两个槽交替写入，所以要改分区表。分区表位于 flash 固定地址，**不能通过 OTA 自己改**，第一次必须用 USB 烧录一次。此后所有升级都走远程。 |
| 升级期间断电/断网会不会变砖 | **不会**。新固件写入备用槽，写完校验通过才切换启动槽；写一半断电，下次仍从旧槽启动。新固件启动后若 30 秒内没有"报平安"，bootloader 自动回滚到旧版。 |
| 用户设置会不会丢 | **不会**。NVS 分区（Wi-Fi、SIP、API Key、音量等）位置不变，升级不触碰。 |
| 唤醒词模型要不要每次重下 | **不要**。模型包独立分区，固件升级不碰它。只有模型本身更新时才单独下发（极少）。 |
| 工作量 | 固件端约 1 天，服务器端半天，首批设备 USB 刷一次分区。 |

## 2. 现状与约束

**现有分区（16 MB flash）**

```
nvs       0x9000    20 KB    设置
otadata   0xe000     8 KB    OTA 启动槽记录（已存在，可直接复用）
app0      0x10000    4 MB    固件（当前 2.39 MB）
model     0x410000   4 MB    ESP-SR 唤醒词模型包（3.25 MB）
ffat      0x810000  7.9 MB   FAT 文件系统（代码里完全没用到）
coredump  0xFF0000  64 KB
```

**已具备的条件**

- `otadata` 分区已存在。
- bootloader 已开启 `APP_ROLLBACK_ENABLE`（升级后需调用 `esp_ota_mark_app_valid_cancel_rollback()` 确认，否则自动回滚）。
- core 自带 `Update.h`（写 flash）、`HTTPUpdate.h`（从 URL 拉取并写入，支持 HTTPS、进度回调、重定向）、`HTTPUpdateServer.h`（网页上传）。
- 设备已有 80 端口 WebServer（配网/设置页）和 mbedTLS（已在用 WSS 连 Qwen）。
- 已有一台静态文件服务器（`ssh vm`，`/opt/handbook`，端口 18090，放设备手册的那台）可直接用来托管固件。

**本设备特有的限制（方案要绕开）**

- **内部 RAM 紧张**：语音会话期间内部堆只剩约 50 KB，不够 TLS 下载。→ 升级只在**休眠/空闲**状态执行（此时约 110 KB 可用），通话或对话中一律不升。
- **Wi-Fi 常常偏弱**（实测 -70 ~ -82 dBm）：2.4 MB 下载可能慢或中断。→ 下载失败不影响旧固件；加重试；信号低于 -75 dBm 不主动开始。
- 单核音频任务 CPU 已接近饱和：升级期间停掉唤醒词检测与音频任务，避免写 flash 时丢帧或看门狗。

## 3. 方案总览

```
                ┌────────────────────────────────────────┐
                │  固件服务器（vm:18090 或任意 HTTPS 静态站）  │
                │   /fw/aicc_phone/firmware.json         │
                │   /fw/aicc_phone/aicc_phone-1.1.0.bin  │
                └───────────────┬────────────────────────┘
                                │ HTTPS GET
   ┌──────────────┐   ① 定时/手动检查版本    ┌────────────┴───────────┐
   │ 管理员浏览器 │ ───────────────────────▶ │  话机（空闲时）         │
   │  设备网页     │   ② 本地上传 .bin（备用）  │  比较版本 → 下载到备用槽 │
   └──────────────┘ ───────────────────────▶ │  校验 SHA256 → 切槽重启  │
                                             │  启动成功 → 报平安       │
                                             │  失败/超时 → 自动回滚    │
                                             └────────────────────────┘
```

两条升级通道，**都做**，互为补充：

| 通道 | 场景 | 实现 |
|------|------|------|
| **A. 服务器拉取（主）** | 批量远程升级。设备每天空闲时查一次 `firmware.json`，有新版就下载；管理员也可在设备网页点"检查更新/立即升级"。 | `HTTPUpdate` + 版本 JSON |
| **B. 网页上传（备）** | 现场工程师、单台调试、服务器不可达时。浏览器打开设备网页，选 `.bin` 上传。 | `HTTPUpdateServer`（或自写 `/update` 端点 + `Update.h`） |

## 4. 分区改造（一次性，USB）

新分区表 `aicc_phone/partitions.csv`：

```
# Name,    Type, SubType, Offset,    Size
nvs,       data, nvs,     0x9000,    0x5000
otadata,   data, ota,     0xe000,    0x2000
app0,      app,  ota_0,   0x10000,   0x400000     # 4 MB 槽 A
app1,      app,  ota_1,   0x410000,  0x400000     # 4 MB 槽 B（新增）
model,     data, spiffs,  0x810000,  0x400000     # 模型包（地址后移）
ffat,      data, fat,     0xC10000,  0x3E0000     # 缩到 3.9 MB（本来没用）
coredump,  data, coredump,0xFF0000,  0x10000
```

要点：

- `nvs`、`otadata`、`app0` 地址不变 → **用户设置保留**。
- 固件 2.39 MB，4 MB 槽留有 1.6 MB 增长空间；若将来想把 ffat 留大些，两个槽各 3 MB 也够。
- `model` 地址从 0x410000 移到 0x810000，代码按分区**名字**访问（`esp_srmodel_init("model")`），不用改代码，但**模型包要随这次 USB 烧录重刷一次**（`tools/flash.sh <port> --models`），之后固件 OTA 不再碰它。
- `ffat` 内容清空（里面本来什么都没有）。

这次 USB 烧录是整个方案里**唯一需要接线**的一步。出厂/首批安装时做掉，后续全部远程。

## 5. 设备端实现

### 5.1 新增模块 `ota.h / ota.cpp`

```
ota_begin()            开机调用：若本次是升级后首次启动，做自检后 mark_valid（报平安）
ota_check(url)         拉 firmware.json，比较版本，返回 {hasUpdate, version, url, sha256, notes}
ota_start(url, sha256) 条件检查 → 停音频/唤醒 → HTTPUpdate 下载写备用槽 → 校验 → 重启
ota_state()            IDLE / CHECKING / DOWNLOADING(百分比) / VERIFYING / REBOOTING / FAILED(原因)
```

**开始升级的前置条件（任一不满足则拒绝并提示）**

- 不在通话中、不在语音会话中（`assistant_state()` 为 SLEEP/FAILED）
- Wi-Fi 已连接且 RSSI ≥ -75 dBm
- 内部空闲堆 ≥ 80 KB
- 新版本号 > 当前版本号（手动强制升级可跳过此项，用于回退）

**报平安（防变砖的关键）**

新固件启动后，`ota_begin()` 检查 `esp_ota_get_state_partition()`，若为 `PENDING_VERIFY`，等到 Wi-Fi 连上、音频初始化成功、网页服务起来之后，调用 `esp_ota_mark_app_valid_cancel_rollback()`。若新固件在这之前崩溃或卡死，看门狗复位后 bootloader 自动切回旧槽。

### 5.2 网页（`web_portal.cpp`）新增一张卡片「固件升级」

- 显示：当前版本、升级服务器地址、上次检查时间、可用新版本与更新说明
- 按钮：**检查更新**、**立即升级**、**从文件上传**（通道 B）
- 升级中显示进度条；完成后页面提示"设备正在重启，约 20 秒后刷新"
- 设置项（存 NVS）：升级服务器 URL、是否自动检查（默认开）、自动检查时间（默认凌晨 4 点）
- 新增端点：`GET /ota/check`、`POST /ota/start`、`POST /ota/upload`、`GET /ota/status`

### 5.3 圆屏显示

升级期间全屏显示"正在升级 xx%，请勿断电"，禁用触摸；完成后显示"升级完成，重启中"。

### 5.4 自动检查策略

- 每天固定时间（默认 04:00，可配）且设备处于休眠态时检查一次；有新版且满足前置条件则自动升级。
- 考虑酒店场景：避开有人使用的时段；升级完成后设备回到休眠，不打扰。
- 可选：`firmware.json` 里带 `rollout_percent` 字段做灰度，设备按 MAC 哈希决定是否属于本批。

## 6. 服务器端

任意能提供 HTTPS 静态文件的地方都行。建议直接用现有 `vm` 上的静态站，新开一个目录：

```
/opt/handbook/fw/aicc_phone/
  firmware.json
  aicc_phone-1.1.0.bin
  aicc_phone-1.0.0.bin        # 保留上一版，便于远程回退
```

`firmware.json`：

```json
{
  "device": "aicc_phone",
  "version": "1.1.0",
  "url": "https://<host>/fw/aicc_phone/aicc_phone-1.1.0.bin",
  "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "size": 2393440,
  "min_version": "1.0.0",
  "notes": "新增查时间工具；联网搜索可配置",
  "rollout_percent": 100,
  "released": "2026-11-23"
}
```

发布脚本 `tools/release.sh`（新增）：编译 → 读取 `FW_VERSION` → 计算 SHA256 → 生成 `firmware.json` → `scp` 到 vm → 完成。一条命令发版。

**HTTPS**：设备下载走 HTTPS。两种做法：
- 简单：不校验证书（和当前连 Qwen 一样），靠 SHA256 保证固件完整性。
- 严格：把服务器 CA 内置到固件校验。酒店内网或可控服务器，用简单做法足够；固件完整性由 SHA256 兜底，被篡改的包写不进去。

## 7. 安全与可靠性

| 风险 | 对策 |
|------|------|
| 写一半断电 | 写入备用槽，旧槽完好；重启仍跑旧版 |
| 新固件起不来 | bootloader 自动回滚（已启用），`ota_begin()` 报平安机制 |
| 下载内容损坏/被篡改 | 下载完校验 SHA256，不符则丢弃，不切槽 |
| 网页上传被滥用 | `/ota/*` 端点加密码（复用设置页口令，或单独 OTA 口令） |
| 升错设备型号 | `.bin` 头部带 `aicc_phone` 魔数 + 板型字段，设备校验后才写 |
| 弱网下载失败 | 失败不影响运行；下次检查再试；RSSI 门槛 |
| 升级打断客人使用 | 只在休眠态、凌晨时段执行 |
| 降级 | 允许手动指定旧版本 URL 强制升级（服务器保留历史包） |

不做的事：Secure Boot / Flash 加密。这两项一旦烧熔丝不可逆，且开发调试成本高，对酒店内网设备收益不大。先不碰。

## 10. 常见问题

**Q：已经装在房间里的设备，怎么过渡到可 OTA？**
每台必须 USB 刷一次新分区表。建议在下一次巡检时统一做，或出厂前做掉。刷完之后永远不用再接线。

**Q：模型包将来要更新怎么办？**
单独做一个"模型 OTA"：下载到 model 分区（用 `esp_partition_write`），更新时暂停唤醒词。频率极低，可后续再加。

**Q：能不能用 Arduino IDE 的网络端口（ArduinoOTA）？**
可以作为开发期便利，但它只适合同一局域网、无版本管理、无回滚语义，不适合酒店批量运维。生产用第 3 节的方案。

**Q：升级包多大、下多久？**
约 2.4 MB。信号好时 10–20 秒，弱信号可能 1–2 分钟。只在空闲时做，用户无感。
